polyagent-mcp — rebrand, poda e independência de engine

Tirar a identidade Cursor do projeto, remover as tools mortas e desacoplar as tools auxiliares do codex.

C

Contexto

O projeto nasceu como ponte para o Cursor CLI, mas virou uma frota multi-engine: codex, grok e claude são os caminhos padrão e o Cursor ficou como fallback opt-in atrás de CURSOR_BRIDGE_ENABLE_CURSOR. O nome do pacote, o bin, o nome do server MCP e 17 variáveis de ambiente ainda anunciam um vendor que hoje é a última opção da lista.

Em paralelo, o inventário acumulou peso morto: plan e build não são usadas. E quatro tools auxiliares têm engine: "codex" hardcoded em src/index.ts (228, 256, 275, 289) — explore, read_slice e web_lookup em modo read-only, e run_filtered com acesso total via force: true. A única configuração existente é CURSOR_BRIDGE_EXPLORE_MODEL: um único model id compartilhado pelas quatro, sem escolha de engine.

Cota esgotada no codex derruba as quatro de uma vez, com erro cru do CLI, sem dizer que grok e claude estavam disponíveis. O fallback atual (isCodexEnvError + FALLBACK_ENGINE_ORDER) cobre só falha de ambiente, nunca cota.

Ao desacoplar do codex aparece uma trava de segurança: no nível do engine, só o codex tem read-only duro. buildGrokArgs ignora mode e emite sempre --always-approve (cli.ts:356); no claude, mode emite --dangerously-skip-permissions (cli.ts:425). O read-only engine-agnóstico vem do bwrap — que hoje degrada em silêncio se ausente.

O spike spikes/quota-patterns.md (14/09/2026) mostrou que o obstáculo é anterior à classificação: nos três CLIs o erro estruturado sai em stdout, e runOnce monta o erro do processo como stderr.trim() || stdout.trim() (cli.ts:688-720) — qualquer conteúdo em stderr descarta o JSON útil.

US-006 Blocked · US-004, US-005

Como usuário, quero que cota esgotada retorne um erro acionável nomeando os engines disponíveis, para que eu decida a troca em vez de receber erro cru do CLI.

  • AC: classifyQuotaError({ stdout, stderr, exitCode }, engine) é função pura em cli.ts e retorna "quota_exhausted" | "rate_limited" | null. A assinatura recebe os três streams porque o sinal vive em stdout, não em stderr (ver spike).
  • AC: A classificação lê primeiro campos JSON estruturados e só depois aplica regex sobre as mensagens de erro extraídas. Fonte dos padrões: spikes/quota-patterns.md, com a evidência de cada um.
  • AC: exitCode === 0 nunca classifica como cota — guarda contra uma resposta bem-sucedida que apenas mencione essas mensagens.
  • AC: rate_limited (throttle transitório) é distinto de quota_exhausted (cota do plano acabou). Trocar de engine resolve o segundo; o primeiro pede espera — e sua mensagem diz exatamente isso, sem sugerir troca de engine.
  • AC: Teste por engine com fixtures de stdout montadas a partir das mensagens canônicas do spike (nenhuma cota foi esgotada para capturá-las), cobrindo os dois tipos e o caso negativo.
  • AC: Ao classificar cota, a chamada falha com <engine> quota exhausted — available engines: <lista> — retry with engine:"<sugestão>". Nunca retenta sozinha.
  • AC: A lista vem de hasEngine(), exclui o que estourou, respeita POLYAGENT_ENABLE_CURSOR e é intersectada com a matriz de capacidade da US-004 — nunca sugerir um engine que a resolução daquela tool recusaria. Sem nenhum candidato válido, o erro diz isso em vez de sugerir lista vazia.
  • AC: Vale para todas as tools que passam por runCursor, delegate incluído. Onde a tool expõe engine (as quatro auxiliares), a sugestão é esse parâmetro. No delegate, que não o expõe, a sugestão é o menor level de 1 a 5 cujo engine primário ainda está disponível. Em fast_delegate, fan_out e generate_image a mensagem informa a cota sem sugerir parâmetro; em follow_up informa que o engine está preso à sessão retomada.
  • AC: Cota é distinta de isCodexEnvError: só a de ambiente cai no FALLBACK_ENGINE_ORDER automático.
  • AC: usage.ts registra cota com outcome próprio e computeEngineHealth o ignora explicitamente — hoje qualquer outcome que não seja failure/timeout conta como sucesso (usage.ts:130), o que inflaria o health de um engine sem cota.
  • AC: Typecheck passes e npm test verde.

I

Impacto esperado

O projeto passa a se apresentar pelo que faz — delegar para uma frota de coding agents com economia de contexto — em vez de pelo vendor que originou o código. É pré-requisito para qualquer divulgação pública: hoje o nome afasta exatamente quem procura essa ferramenta e não usa Cursor.

Operacionalmente, cota esgotada deixa de ser beco sem saída: a resposta nomeia o que fazer, e a configuração por tool permite distribuir o consumo entre as três assinaturas de forma permanente em vez de concentrar tudo no codex.

US-005 tem valor próprio além de habilitar a US-006: hoje qualquer falha de CLI que escreva em stderr descarta o diagnóstico estruturado de stdout, o que degrada toda mensagem de erro do bridge, não só as de cota.

Limites do tier full: 8 user stories, one-shot, sem features/.
